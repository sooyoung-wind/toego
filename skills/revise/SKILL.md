# 학술 원고 퇴고 (HWP → 검토 → 비교 HTML)

심사 의견에 답하는 퇴고의 기준은 문장을 매끄럽게 다듬는 것이 아니다. **모든 문장이 저자가 실제로
수행한 분석과 그 결과로 뒷받침되는가**가 먼저이고, 문체는 그다음이다.

입력: `$ARGUMENTS` — 첫 인자는 저자 정보(이름·소속·이메일)를 뺀 심사용 원고(.hwp), 나머지는 수치 대조에 쓸 근거 자료 폴더(표·결과 CSV,
심사 응답 초안 등, 선택). 심사 의견 원문은 사용자 메시지에서 받는다. 없으면 일반 학술 퇴고 기준으로 진행한다.

## 도구

모든 스크립트는 이 skill 폴더 안에 있다. 표준 라이브러리 외 의존성은 HWP 추출에만 필요하며,
아래 고정 버전을 `uv`가 실행 시점에 PyPI에서 받는다(사용자 환경에 설치하지 않음).

```bash
OUT=./toego/<원고 이름>          # 작업 폴더(현재 디렉터리 아래)
uv run --frozen --quiet --no-project --python 3.11 --with pyhwp==0.1b15 --with six==1.17.0 \
  --with lxml==6.1.3 --with beautifulsoup4==4.15.0 \
  python ${CLAUDE_SKILL_DIR}/scripts/hwp_extract.py "<원고.hwp>" $OUT/extract
uv run --frozen --quiet --no-project python ${CLAUDE_SKILL_DIR}/scripts/lint_ko.py $OUT/extract > $OUT/lint.json
# ... $OUT/review.json 작성 ...
uv run --frozen --quiet --no-project python ${CLAUDE_SKILL_DIR}/scripts/build_html.py $OUT/review.json $OUT/extract $OUT/퇴고_비교.html
```

| 스크립트 | 하는 일 |
|---|---|
| `hwp_extract.py` | 본문 문단(id=`절-P번호`)·문장, 표, 캡션, 내장 그림(`extract/html/bindata/`) 추출 |
| `lint_ko.py` | 오탈자 사전, 단정·과장 어휘, 번역투, 시제 후보, 단위 표기, 문두 접속어 반복, Fig/Table 첫 인용 순서 |
| `build_html.py` | 원문은 id로 가져와 어절 diff, 수정 근거 표, 복사 버튼, 반영 체크가 있는 단일 HTML |

`uv`가 없으면 사용자에게 설치를 안내하고 멈춘다. 추출기가 이메일 주소 경고를 내면 작업을 멈추고, 저자 정보를 지운 원고를 다시 달라고 요청한다. 수식 개체는 텍스트로 나오지 않으므로(번호만 남음)
수정안에 `[원문 수식]`으로 표시한다. .hwpx는 한/글에서 .hwp로 저장해 달라고 요청한다.

## 절차

1. **추출·선별.** 추출 후 린터를 돌린다. 린터 결과는 "볼 곳"이지 판정이 아니다.
2. **근거 수집.** 원고의 표(`tables.json`)와 그림(PNG를 직접 열어 본다), 사용자가 준 근거 폴더를 대조한다.
   본문 수치가 표·그림·원자료와 다르면 `사실오류`다. 그림에 대한 서술("모든 구간에서", "유사한 패턴")은
   반드시 그림을 열어 확인한다.
3. **문장(1).** 각 문장: 결과로 뒷받침되는가 / 범위를 넘는가 / 내용 없는 상투인가 / 주술 호응·조사 /
   시제 / 용어 통일. 장·절별로 `sentence-auditor` 에이전트를 병렬로 쓸 수 있다.
4. **문단(2·3).** 문장끼리 인과·대조가 맞는지, 위치에 맞는 괄식인지 보고, **수정 후 문단**을 한 문장으로 요약한다.
5. **절(4).** 문단 요약을 이어 읽어 논증이 끊기거나 반복되는 곳을 찾는다. 4-6단계는 `paragraph-auditor`.
6. **전체(5·7).** 서론이 제기한 질문 → 본문 근거 → 결론 반영을 표로 대응시킨다. 결론에 없는 결과,
   근거 없는 결론 문장, 불리한 결과의 누락을 찾고 장·절 구조 변경안을 낸다.
7. **초록(6).** 국문 본문·결론과 같은 범위·수치인지, 비교 대상이 명시됐는지, 시제가 맞는지.
8. **검증.** `fact-checker`로 review.json의 모든 수치·주장을 원자료와 독립 대조하고, 지적을 반영한다.
9. **HTML(8).** build_html.py로 만든다. 가능하면 브라우저로 열어 데스크톱·모바일 폭에서 확인한다.

## 판정 규칙

**시제**
- 서론: 선행연구 보고 = 과거(보고하였다), 표준·일반 사실 = 현재(정의한다), 목적 = 현재(제안한다)
- 방법: 저자가 수행한 절차 = 과거(적용하였다), 구조·알고리즘·수식의 성질 = 현재 허용(구성된다)
- 결과: 관찰 수치 = 과거, 표·그림 설명 = 현재(Table 3은 … 비교한 것이다), 해석 = 현재 + 완화(… 로 해석된다)
- 결론: 수행·결과 = 과거, 시사점·한계 = 현재

**괄식** — 서론: 깔때기형, 문단은 두괄식 / 방법: 두괄식 / 결과: 두괄식(핵심 결과 → 수치 → 해석) /
고찰: 양괄식 / 결론: 양괄식(요약 → 정량 결과 → 범위와 한계). 절의 마지막 문단은 미괄식 허용.

**반드시 잡을 것**
- 한정된 자료(한 사이트, 한 기간, 한 데이터셋)의 결과를 방법 일반의 성질로 쓴 문장(능가, 입증, 일관되게, demonstrate)
- 보정·학습에 쓴 자료에서의 성능을 성과처럼 쓴 문장
- 표·그림과 다른 서술, 불리한 수치의 누락(선택적 보고)
- 학습 자료와 평가 자료가 겹치는 비교를 독립 검증처럼 쓴 문장
- 같은 기호가 다른 뜻으로 쓰인 곳(예: 초과확률 P90과 분위수 P90)
- 내용 없는 주제문("한계점이 존재하게 된다", "다른 양상을 보였다"), 수사("핵심 신호", "다각도로")
- 다른 절과 같은 내용의 반복, 결과 표를 방법 절에서 먼저 인용하는 등 인용 순서 오류

**하지 않을 것** — 뒷받침되는 문장을 취향으로 바꾸기, 확인 못 한 사실을 수정안에 단정하기
(대신 `[확인: …]`과 `check` 항목), 저자가 하지 않은 분석을 수정안에 넣기.

## review.json 형식

`${CLAUDE_SKILL_DIR}/examples/review.sample.json`(합성 예시)이 최소 예시다.

```jsonc
{
 "meta": {"title","source","date","reviewer_comment","evidence_sources":[]},
 "rules": {"tense":[[위치,시제,예]], "structure":[[위치,형식,이유]], "flags":[[유형,뜻]]},
 "structure": {"before":[], "after":[], "reasons":[[변경,왜]]},
 "sections": [{"id","title","pattern","flow_before","flow_after","verdict",
   "paras":[{"id":"2.1-P2","status":"수정|유지|삭제|병합|이동|분할|신설|재작성|확인필요",
     "pattern":"두괄식","summary":"수정 후 문단 한 문장 요약","after":"수정 후 전문(문단 구분은 \n\n)",
     "before":"(신설 문단만)","edits":[{"t":"유형","b":"수정 전 구절","a":"수정 후 구절","why":"근거"}],
     "check":["저자 확인"]}]}],
 "abstract": {"before","after","edits":[],"note"},
 "captions": [{"target","before","after","why"}], "references": [{"ref","issue","fix"}],
 "global_flow": {"question_to_conclusion":[[질문,근거,결론 반영]],"verdict","paragraph_chain"},
 "author_checks": [], "fact_checks": [[항목,결과,출처]]
}
```

`why`에는 "어색하다" 같은 인상이 아니라 **무엇이 사실·논리·규칙과 어긋나는지**를 쓰고, 수치 근거는 출처
파일이나 표 번호를 적는다. 유형: 과잉일반화 근거부족 사실오류 AI상투 논리연결 시제 문법 오탈자 용어통일 중복 구조 인용.

## 마무리

사용자에게 HTML 경로, 수정 건수(유형별), 저자 확인이 필요한 항목 중 가장 중요한 것을 알린다.
원고와 추출 결과는 미발표 자료일 수 있으므로 외부에 게시하지 않는다.
